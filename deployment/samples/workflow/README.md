# 审批样例置备

`workflow-samples.json` 定义可直接验收的分类、表单、流程节点和身份自然键。置备脚本只调用平台正式 API，不直接写 Flowable 或业务表，也不包含账号密码和固定数据库主键。

在本地服务已启动、公司测试角色和账号已经建立后执行。密码只通过进程环境变量传入，脚本不会输出或持久化密码：

```powershell
$env:APPROVA_SAMPLE_ADMIN_PASSWORD = '<管理员密码>'
node .\deployment\scripts\provision-workflow-samples.mjs --username admin
Remove-Item Env:APPROVA_SAMPLE_ADMIN_PASSWORD
```

脚本先通过角色菜单增量授权 API 为五个公司参与者角色追加待办、待签、详情、审批、认领权限及必要父菜单。该接口只插入缺失关联，不读取、替换或删除角色已有菜单。随后脚本按自然键查询当前用户、角色和部门，创建或复用分类及表单，保存经过后端安全校验的 BPMN，最后部署未部署的样例模型。

重复执行时，分类名称、同名表单 JSON、模型元数据、模型 BPMN、部署快照和已部署 BPMN 必须与目录一致；任何重复名称、标识碰撞或内容漂移都会明确失败，不会静默覆盖正式资产。已经一致的已部署模型会返回真实 `deploymentId` 并跳过部署，避免重复产生流程定义版本。

当前样例包括：

- 请假申请：部门负责人角色认领，总经理角色审批。
- 费用报销：财务部门认领，总经理直接审批。
- 采购申请：采购负责人、财务负责人、总经理三级审批。
- 合同审批：文控专员、总经办、总经理三级审批。
- 用印申请：文控角色认领，总经办角色审批。

每个样例至少包含两个串行用户任务。第二级及后续办理人可以通过正式“退回”动作选择已完成的上级审批节点；首个审批节点没有历史用户任务，不能伪造退回目标。
