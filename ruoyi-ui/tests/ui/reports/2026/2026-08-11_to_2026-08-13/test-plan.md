# 审批引擎 2026-08-11 至 2026-08-13 UI 测试计划

## 目标

通过 Chromium、真实前后端服务、MySQL、Redis 和 Flowable 运行环境，对审批引擎的主要用户入口、核心审批链路、权限、数据一致性及故障恢复能力进行一次完整 UI 复测，并形成可机械对账的最终结果。

## 范围

- 登录、验证码、账号停用、五类工作流角色、菜单、页面及按钮权限。
- 分类、表单、模型、设计器、版本、部署、挂起、激活和删除门禁。
- 单级及多级审批、认领、取消认领、驳回、撤回、委派、转办、退回、重提和终止。
- 用户、角色、部门、直属上级、部门负责人和表单用户字段等办理人来源。
- ALL/ANY 多实例、发起时或办理时选人、加签、减签、并发 revision 冲突。
- 表单校验、节点字段权限、草稿、附件、并发提交和定义版本过期。
- 排他、包容、并行、事件网关、受控循环及高级 BPMN 元素。
- DMN、集成凭据、HTTP/SQL 扩展、通知、SLA、多池协作和 XLSX 导出。
- MySQL、Redis、附件存储、SMTP、HTTP、后端重启及浏览器异常场景。

## 执行原则

- 分类、表单、模型、部署、发起、审批和运维操作通过真实页面完成，不以 mock、localStorage 或 XML 注入代替用户链路。
- API 和 SQL 仅用于只读核验、权限拒绝及零副作用证明；核心写操作走正式 UI 和后端接口。
- 使用单个 Chromium worker，按 `smoke -> full -> fault` 顺序执行；业务缺陷不阻断相互独立的后续用例。
- 每个计划用例只能有 `passed`、`failed`、`blocked` 或 `not executed` 一个最终状态，不保留 `pending`。
- 未配置真实短信通道时，短信成功投递必须标记为 `not executed`，不得使用 mock 冒充通过。
- 凭据仅通过本机运行配置或进程环境提供，不写入测试报告、截图说明或 Git 历史。

## 环境与工具

- 前端：Vue 3 / Vite，`http://127.0.0.1:1024`
- 后端：Spring Boot / Flowable，`http://127.0.0.1:8080`
- 自动化：`@playwright/test 1.62.0`、Chromium、1440x960 主视口
- 补充视口：1366x768、1920x1080
- 数据服务：真实 MySQL、Redis；故障阶段使用受控本机 SMTP 和 HTTP 服务
- 总控入口：`deployment/scripts/run-ui-tests.ps1`
- 聚合口径：最终批次 `run-state.json`；Playwright 分片 `results.json` 和 `junit.xml` 不作为全量计数来源

## 通过条件

- 每项通过用例均完成真实 UI 操作，并按场景核对页面、接口读取结果、业务表、Flowable 状态、附件或审计记录。
- 拒绝和故障场景验证用户可理解的错误、事务回滚、零副作用及恢复后的状态一致性。
- 总数与最终状态清单完全一致，且没有未归类的 `pending` 用例。
- 测试结束后恢复开发前后端参数，释放故障服务端口和临时 ACL，删除运行输出、数据库备份、trace、截图和日志等副产物。
