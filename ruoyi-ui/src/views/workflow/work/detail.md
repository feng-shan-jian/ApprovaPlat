# WorkflowProcessDetail

## 组件简介

`detail.vue` 是流程实例的授权聚合详情页，负责展示当前任务表单、历史表单、流程图、流转记录和动态多实例成员，并提供通过、驳回、退回、委派、转办、取消认领、完成委派及动态加签/减签入口。页面只调用真实工作流 API，不缓存业务状态到浏览器本地存储。

## 使用方式

组件由工作流详情路由直接加载，不接收 props，也不对外 emits。路由必须提供流程实例主键，可选提供任务主键；详情 API 会再次校验任务与实例关系及当前用户的对象权限。

```js
router.push({
  name: 'WorkflowProcessDetail',
  params: { instanceId: processInstanceId },
  query: { taskId, source: 'todo' }
})
```

## Props

无。流程实例、任务和来源上下文来自当前路由。

## Emits

无。成功动作通过真实 API 持久化后刷新聚合详情，失去任务对象权限的动作会返回来源列表。

## 公开方法

无。页面动作均为组件内部方法，不通过 `defineExpose` 对外开放。

## 关键设计

- 页面能力以详情 API 返回的活动任务、办理人、流程状态、`returnAllowed` 和动态多实例投影为准，前端门禁不能替代后端权限与状态校验。
- 退回入口只在 `returnAllowed=true` 时显示和提交。退回不选择节点，后端把当前申请整实例直接交给发起人修改；发起人进入“待修改”详情后编辑原开始表单，原表单变量按覆盖语义保存，重新提交后恢复首审办理配置并重新按原审批链流转。复杂执行树仍由后端按真实 execution 关系拒绝并保持零副作用。驳回继续按整实例终止语义开放。
- 当前任务表单按部署 schema 校验；附件只提交正式附件 UUID，并通过授权元数据接口完成回显。
- 动态加签、减签和完成共享服务端 revision 契约。完成弹窗打开时冻结 `multiInstanceState.revision`，普通或静态任务不发送 `expectedRevision`。
- 动态调整成功后的详情重载只关闭弹窗，不会在关闭动画中提前重置 `ADD`/`REMOVE` 动作、成员目标或目录缓存；从 `close` 到 `closed` 的完整区间由关闭期锁禁用加签、减签入口，`closed` 后才清理草稿并解锁。用户连续执行加签、减签时，上一轮弹窗身份和回调不得清空下一轮真实提交参数。
- 下一办理人字段只接受详情 API 的 `nextUserAssignmentPolicy`：`DISABLED` 隐藏、`OPTIONAL` 可选、`REQUIRED_ALL` 会签必填、`REQUIRED_ANY` 或签必填。兼容旧后端时只继承可证明的必填 ALL/ANY，非必填能力失败关闭为 `DISABLED`，不从 BPMN 或 409 试错推断。
- 动态完成或成员调整只有在业务码为 `409` 且机器子码精确等于 `WORKFLOW_MULTI_INSTANCE_REVISION_CONFLICT` 时，才调用 `getMultiInstanceState` 或重载详情获取最新 revision。刷新成功只替换成员快照，保留办理意见、抄送人、下一办理人、表单值和附件草稿，并要求用户明确再次提交；其他 409 按原始状态冲突展示，不伪装成成员变化。
- 强制刷新确认原任务已失效时，页面关闭办理弹窗并完整重载详情，避免对历史任务重复提交。
- 普通完成、退回、驳回、委派和转办在异步表单校验前即占用动作锁；请求期间禁止关闭弹窗，失败时保留意见、表单和身份选择并展示稳定错误，避免双击并发和不可恢复输入丢失。
- 普通动作弹窗打开时冻结流程实例、任务主键和详情加载序号。退回节点查询、表单异步校验和最终写请求都会复核该上下文，路由切换后的晚到响应只能被丢弃，不能重新打开弹窗或改为操作新任务。
- 委派办结复用正式办理弹窗，要求受托人填写真实意见并可选择抄送人；当前任务表单保持只读，办结不结束 owner 的审批任务，也不提交 owner 的任务变量。成功后返回来源列表，`403/404/409` 表示对象已失效时同样退出过期详情。
- 普通动作弹窗与动态调整弹窗都只在 `closed` 后仍保持关闭时清理草稿，旧关闭动画不能清空随后打开的新任务输入。
- 流转记录只显示详情 API 明确投影且不超过 8 KiB UTF-8 正文门禁的 `comment.opinion`。兼容响应中的内部 `message`、`audit` 会在详情写入页面状态前删除，前端不解析审计 JSON，也不把操作人、revision 等内部字段作为审批意见展示。
- 动作分发只接受完成、退回、驳回、委派、转办和取消认领白名单；未知内部状态会在调用 API 前失败，不会显示无业务副作用的成功提示。
- 委派、转办、下一办理人和动态加签只展示服务端 `capability=approval` 的正式 RBAC 结果；抄送人继续使用通用启用用户目录，两套缓存和加载态完全隔离。
- 动态加签的远程检索缓存只负责当前弹窗的已选标签展示，不参与提交资格判定，避免连续加签/减签时关闭动画清理缓存后误拦截合法选择；后端写命令仍会在事务内独立复核审批资格、对象权限和任务状态。

## 最小接入示例

父级 `/workflow/process-detail` 下的隐藏路由子项示例：

```js
{
  path: ':instanceId',
  component: () => import('@/views/workflow/work/detail.vue'),
  name: 'WorkflowProcessDetail',
  meta: { title: '流程详情', noCache: true }
}
```

详情页依赖 `workflow:process:approval`、`workflow:process:claim` 等既有权限字符。最终动作权限、对象归属、状态迁移、revision CAS、审计与持久化均由后端再次执行。
