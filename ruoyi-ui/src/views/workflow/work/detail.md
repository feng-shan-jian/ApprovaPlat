# WorkflowProcessDetail

## 组件简介

`detail.vue` 是流程实例的授权聚合详情页，负责独立展示申请表单、本节点办理表单、历史节点表单、流程图、流转记录和动态多实例成员，并提供通过、驳回、退回、委派、转办、取消认领、完成委派及动态加签/减签入口。页面调用真实工作流 API，业务状态统一由服务端持久化并投影到页面。

## 使用方式

组件由工作流详情路由直接加载。路由必须提供流程实例主键，可选提供任务主键；详情 API 会再次校验任务与实例关系及当前用户的对象权限。

```js
router.push({
  name: 'WorkflowProcessDetail',
  params: { instanceId: processInstanceId },
  query: { taskId, source: 'todo' }
})
```

## Props

无。流程实例、任务和来源上下文来自当前路由。

## Emits

无。成功动作通过真实 API 持久化后刷新聚合详情；任务对象权限失效时返回来源列表。

## 公开方法

无。页面动作均封装为组件内部方法。

## 关键设计

- 页面能力由详情 API 返回的活动任务、办理人、流程状态、`returnAllowed` 和动态多实例投影共同确定；后端在每个写命令中执行权威权限与状态校验。
- `processFormList` 中唯一 `taskId=null` 的正式开始提交快照是“申请表单”，其余记录是历史节点表单；当前 UserTask 的 `currentTaskForm` 是独立的“本节点办理表单”，节点绑定表单时显示该页签。退回态把后端绑定当前任务的开始表单投影显示为可编辑“修改申请表单”，节点历史保持独立投影。
- 默认页签顺序固定为：退回态申请表单；正常态优先显示本节点表单，其次显示申请表单。唯一开始提交快照缺失时固定显示默认流程图和“申请表单快照缺失”；多个开始快照或退回投影身份串线会使详情加载失败并关闭。
- 退回入口在 `returnAllowed=true` 时显示和提交。服务端使用可信历史中的首审批节点作为退回目标；受控会签/或签一次撤销来源同根全部活动任务并生成一个待修改任务。普通首审批重提在当前任务上恢复退回时冻结的办理配置，来源轮次完成 `RETURNED→REOPENED` 审计关闭；首审批为受控多实例时，按该节点的开始选择、部署配置或正式目录来源重新建组。后续 ALL/ANY 节点在自然重新进入时从各自权威来源建立新轮。静态多实例、CallActivity、跨作用域、边界事件、循环和含副作用路径返回稳定冲突，事务保持零副作用。
- 当前任务表单按部署 schema 校验；附件只提交正式附件 UUID，并通过授权元数据接口完成回显。
- 动态加签、减签和完成共享服务端 revision 契约。完成弹窗打开时冻结 `multiInstanceState.revision`，`expectedRevision` 仅随受控动态多实例任务发送。
- 动态调整成功后的详情重载关闭弹窗并保留 `ADD`/`REMOVE` 动作、成员目标和目录缓存，直至 `closed` 事件清理草稿并解锁。从 `close` 到 `closed` 的完整区间由关闭期锁管理加签、减签入口；连续操作使用各自独立的弹窗身份和提交参数。
- 下一办理人字段使用详情 API 的 `nextUserAssignmentPolicy`：`DISABLED` 隐藏、`OPTIONAL` 可选、`REQUIRED_ALL` 会签必填、`REQUIRED_ANY` 或签必填。该字段直接替换历史字段、BPMN 客户端解析和 409 试错推断，历史字段已从前后端协议删除。
- 动态完成或成员调整在业务码为 `409` 且机器子码精确等于 `WORKFLOW_MULTI_INSTANCE_REVISION_CONFLICT` 时，调用 `getMultiInstanceState` 或重载详情获取最新 revision。刷新成功替换成员快照，保留办理意见、抄送人、下一办理人、表单值和附件草稿，并要求用户明确再次提交；其他 409 按原始状态冲突展示。
- 强制刷新确认原任务已失效时，页面关闭办理弹窗并完整重载详情，新任务快照成为下一次操作的唯一依据。
- 普通完成、退回、驳回、委派和转办在异步表单校验前占用动作锁；请求期间弹窗保持锁定，失败时保留意见、表单和身份选择并展示稳定错误。动作锁串行化提交，输入草稿随当前弹窗生命周期保存。
- 普通动作弹窗打开时冻结流程实例、任务主键和详情加载序号。退回节点查询、表单异步校验和最终写请求都会复核该上下文；路由切换后的晚到响应按冻结上下文丢弃，新任务由新一代详情上下文处理。
- 委派办结复用正式办理弹窗，要求受托人填写真实意见并可选择抄送人；当前任务表单保持只读，owner 的审批任务和任务变量继续保留。成功后返回来源列表，`403/404/409` 表示对象已失效时同样退出过期详情。
- 普通动作弹窗与动态调整弹窗在 `closed` 后仍保持关闭时清理草稿；每次打开使用独立代次标识，随后打开的新任务输入由新代次持有。
- 流转记录显示详情 API 明确投影且通过 8 KiB UTF-8 正文门禁的 `comment.opinion`。内部 `message`、`audit` 在详情写入页面状态前删除，审批意见保持为纯正文投影。
- 动作分发接受完成、退回、驳回、委派、转办和取消认领白名单；未知内部状态在调用 API 前返回失败，页面展示真实业务结果。
- 委派、转办、下一办理人和动态加签只展示服务端 `capability=approval` 的正式 RBAC 结果；抄送人继续使用通用启用用户目录，两套缓存和加载态完全隔离。
- 动态加签的远程检索缓存负责当前弹窗的已选标签展示；提交资格由后端写命令在事务内独立复核审批资格、对象权限和任务状态。连续加签/减签使用独立弹窗代次管理缓存和合法选择。

## 最小接入示例

父级 `/workflow/process-detail` 下的隐藏路由子项示例：

```js
{
  path: ':instanceId',
  component: () => import('@/views/workflow/work/detail.vue'),
  name: 'WorkflowProcessDetail',
  meta: { title: '流程详情', noCache: true }
}
```

详情页继续复用既有权限字符：退回调用 `POST /workflow/task/return` 并要求 `workflow:process:approval`，重提调用 `POST /workflow/task/resubmit` 并要求 `workflow:process:start`；认领等动作保持原权限。最终动作权限、对象归属、状态迁移、revision CAS、审计与持久化均由后端再次执行。
