# HeaderNotice

## 组件简介

顶部消息中心统一承载审批、SLA、BPMN 事件工作流通知与系统公告。工作流通知由业务事务直接写入统一站内收件箱，邮件和短信则通过正式 outbox 投递；系统公告继续复用原有公告读取链路。

## 使用方式

组件不接收业务参数，由主布局直接挂载。它使用当前登录会话和权限集合查询通知、已读状态和用户通道偏好。

```vue
<HeaderNotice />
```

## Props

无。

## Emits

无。流程跳转由组件读取后端返回的受控 `routePath` 并通过 Vue Router 执行。

## 公开方法

无。消息面板打开时自动刷新，用户也可以使用刷新图标重新查询，并通过“加载更多”读取后续分页。

## 关键设计

- 统一工作流通知与系统公告分栏展示，角标汇总两个正式来源的未读数。
- 工作流通知支持全部、未读、已读过滤、稳定分页和全部已读；切换筛选重置第一页，加载更多追加服务端记录。
- 点击工作流通知后先持久化已读状态，再使用服务端返回的受控 `routePath` 进入对象授权页面。
- 偏好采用服务端 revision 乐观锁保存，站内和邮件开关不会写入浏览器本地状态。
- `workflow:notification:list` 控制工作流通知页签及全部收件箱读写请求；无权限用户仍可读取系统公告，但不会发出工作流通知 API 请求。
- 通知偏好的读取、保存和入口复用 `workflow:notification:list`；服务端按当前登录用户隔离个人配置，不要求数据库中不存在的额外权限。
- 组件不解析流程变量、不拼接业务内容，也不持有 SMTP 配置。

## 最小接入示例

```vue
<template>
  <nav class="navbar">
    <HeaderNotice />
  </nav>
</template>
```
