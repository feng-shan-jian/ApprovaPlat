# C01 取证后的资源引用修复包

2026-10-03，基线 `70b2c0a`。真实 MySQL/Flowable 双事务实验复现：模型读取有效分类/表单后暂停，删除事务确认无引用并提交，随后模型继续提交，留下悬空引用。正式复现为 `WorkflowResourceReferenceMysqlTest`，合成数据逐主键清理。

修复使用现有资源行锁：模型及发布写事务读取资源时持共享锁至提交，删除事务按资源主键升序取得排他锁，再检查引用。分类和表单删除各自只锁本类资源，不跨类持锁；模型同时需要时先分类后表单，多个表单按主键升序。删除入口用 READ_COMMITTED，确保等待模型提交后引用查询能看见该提交；不变更工作流引擎既有 REPEATABLE_READ 写边界。只读目录不增加锁。保留无引用检查和原有 404/409 响应，不添加全局锁或数据库结构。

受影响调用方为分类/表单 Mapper、删除服务、ModelService 与作者字段目录。提升旧版本和保存旧版本另存新版本都会复制元数据，必须覆盖 XML 与 metadata.formId 的引用并集；常规保存沿用作者目录的一次读取，额外元数据引用与提升版本共用排序锁定规则。

真实竞争测试共 5 项通过：分类/表单创建与删除交错、分类/表单删除与提升旧版本交错、旧版本保存的 XML 已换表单但元数据仍保留旧表单的交错。最后一项先复现“删除提交后仍成功另存”，再补齐检查。模型版本、编译和字段目录另有 9 项通过，既有查询次数断言未放宽。完整构建与真实业务三链结果并入规则归一执行报告。
