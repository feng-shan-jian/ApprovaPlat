# 工作流用户体验与优化执行计划（2026-09-12）

状态：待执行。本文件定义可实现的页面行为、依赖和验收，不代表新界面或用户测试已经完成。

依据：[原生前端复测报告](/D:/ruoyiflowable/docs/testing/ComputerUseWorkflowRetestReport-20260911.md)及其截图。技术前置见[完整修复执行计划](/D:/ruoyiflowable/docs/testing/WorkflowRepairExecutionPlan-20260912.md)。本轮已查看原报告关键画面，未新增现场交互测试。

## 1. 目标与实施原则

让流程设计者知道如何完成配置、遇错如何修复、离开后如何恢复；让审批人知道正在等待什么及自己要做什么；让集成管理员能够完成端点与凭据配置。

- 沿用现有 Element Plus、品牌颜色、属性面板、工具栏和任务页结构；先解决任务完成率和状态准确性，再做视觉细化。
- 复用已经存在的错误定位、面板宽度调整、小地图、等待事件和正式目录，避免新建重复入口。
- 实施前为受影响页面保留当前截图与交互基线；原报告红/粉色歌词属于桌面悬浮层，不作为产品缺陷。
- 原生操作证据、浏览器自动化证据、源码判断和设计提案分开记录；截图本身不证明键盘或无障碍行为通过。
- 后端能力由 R 任务实施一次；下列 U 任务负责相应用户入口、表达和体验验收，不能重复开发一套协议。

## 2. 用户及主任务

| 用户 | 要完成的事 | 首要体验要求 |
| --- | --- | --- |
| 流程设计者 | 创建/导入、配置、保存、发布和试运行 | 工作不丢、配置可理解、错误可修复 |
| 业务发起人/审批人 | 发起申请、办理待办、查看进度 | 状态准确、待办明确、没有无关技术细节 |
| 集成管理员 | 配置凭据/端点、验证投递和排障 | 权限清楚、准备状态真实、失败有恢复路径 |

主旅程：进入/恢复设计 → 导入及完整性检查 → 节点/字段配置 → 补齐资源 → 保存与纠错 → 发布/试运行 → 业务办理与状态跟踪。

## 4. 页面行为与验收

### U00：建立基线，避免凭印象优化

执行动作：

1. 选取简单单池、A 的完整长图、C 调用映射、F 双池消息四种固定模型，记录当前窗口、缩放、实际操作步骤及问题。
2. 测量“发现错误→定位→修好”“从缺端点→回到原节点继续配置”“进入详情→说清当前状态”的步骤数和用时。
3. 初始样本区分熟悉系统的开发人员与首次使用者；没有实际用户参与时标记专家走查，不报告用户成功率。
4. 建立统一记录表：任务、用户角色、是否完成、耗时、误操作、是否求助、是否重建/重新导入、观察证据。

交付：真实基线和任务脚本。尚未测得的指标填“待测”，不能从截图编造平均用时或满意度。

### U01：让用户始终知道设计是否安全保存

页面入口：[设计页面](/D:/ruoyiflowable/ruoyi-ui/src/views/workflow/model/design.vue)、[工具栏](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/DesignerToolbar.vue)、[标签栏](/D:/ruoyiflowable/ruoyi-ui/src/layout/components/TagsView/index.vue)。

设计行为：

- 标题显示模型名称、版本和明确状态：未保存修改、正在保留草稿、草稿已保留、正式保存成功、保存失败。显示最近成功时间；“设计中”不能代替保存状态。
- 标记与真实服务器确认绑定；网络中断时保留修改，失败信息持续可见并可重试。
- 站内离开时允许“继续编辑”“保留草稿后离开”“放弃修改”；保存失败停留当前页，只有明确放弃才丢弃内容。
- 返回时显示可恢复草稿的时间及模型版本；冲突时解释“模型已被更新”，保留双方内容供选择，不默默载入旧数据覆盖新设计。
- 标签用模型名称和版本区分，未保存加明确标记；保留可辨认的短名，完整名称可查看。
- 从资源页返回原节点，保留缩放与面板分区；浏览器重新启动后的恢复能力以 R01 的服务端草稿为准。

验收：复杂未完成设计经侧栏/标签切换、刷新、会话恢复均不需重画；错误状态不出现“已保存”；同名不同模型和不同版本不串草稿。关闭保护及草稿恢复分别验收。

### U02：把“图能画出来”转为“配置知道怎么补齐”

页面入口：[设计器](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/ProcessDesigner.vue)、[属性面板](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/DesignerPropertiesPanel.vue)、[参与者规则](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/ParticipantRuleEditor.vue)。

设计行为：

1. 导入后展示模型摘要：根流程数量、主要节点数量、需要补齐的表单/发起范围/外部资源；摘要可关闭，可从问题入口重新打开。
2. 多池提供可折叠流程列表，每个根流程显示名称、发起范围、开始表单及缺项数量；点击定位该池所属流程。
3. 属性顶部显示业务名称及“所属流程/当前节点”；技术 ID 可复制但不占主标题。切换池时避免把池属性、流程属性和开始表单混为一页。
4. 缺失值显示未配置；后端明确不支持的组合显示原因，禁止展示假默认值。
5. 节点配置按当前类型呈现“必填业务配置、运行行为、高级属性”；类型转换后提示实际清理内容，可撤销，不让用户处理隐藏遗留字段。
6. 节点标记区分“配置待完成”“有阻断问题”“配置已核验”；状态基于相应校验阶段，不用画布可见冒充部署就绪。

验收：导入缺少第二池范围的模型，不点保存就能发现并定位；单次配置后保存回读一致。G 转信号不再卡死；不会修改其他池的配置。长图中可通过列表/搜索到达目标，无需反复缩放找节点。

### U03：字段映射呈现业务关系和权限

页面入口：[调用领域](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/routingCallActivityDomain.js)、[属性面板](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/DesignerPropertiesPanel.vue)、[表单权限领域](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/formParticipantDomain.js)。

设计行为：

- 输入区用“父流程字段 → 子流程字段”，输出区用“子流程字段 → 父流程结果字段”；展示字段业务名称、类型及所属模板，技术变量名为辅助信息。
- 不可映射项显示具体原因。仅在授权范围内解释，不暴露用户无权查看的字段或模板名称。
- 行内即时提示缺目标、重复目标、类型不兼容；保存时仍消费正式服务器校验。
- 冲突时同时展示两个字段定义和差异，例如类型/必填/范围约束，并提供定位各来源的入口。
- R06 完成后提供“系统回填，用户只读”的明确配置；用户编辑权限与系统输出资格分别展示。后台不支持时不提前开放假开关。
- 对正式模板与内嵌表单使用同一套字段说明；结果预览显示模拟值时明确标为预览，不能被当成运行证据。

验收：用户能说明每条映射的方向及字段来源；原 C 错误能从当前映射行找到原因。真实 7→8 回传可见且结果不可人工编辑，非法直接提交仍被服务端拒绝。

### U04：空目录必须给出下一步

页面入口：[端点管理](/D:/ruoyiflowable/ruoyi-ui/src/views/workflow/connector/index.vue)、[消息配置编辑器](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/CollaborationMessageEditor.vue)、[扩展目录加载](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/extensionEventSlaDomain.js)。

| 服务端状态 | 用户文案示例 | 允许的动作 |
| --- | --- | --- |
| 未配置授权端点 | 当前没有可选接收端点 | 有权限者配置端点；其他人查看配置要求 |
| 授权端点停用 | 该端点已停用，发布前需要处理 | 有权限者进入管理；其他人查看负责人信息（如有） |
| 凭据未就绪 | 接收端点尚未完成认证配置 | 管理员绑定凭据并检查 |
| 权限不足 | 当前账号无法管理连接资源 | 查看所需权限及联系渠道；不泄露无权资源 |
| 加载失败 | 暂时无法加载端点，请重试 | 重试并保留已填写字段 |

向导流程：选择接收方式 → 选择/配置端点 → 绑定授权凭据 → 检查配置及认证 → 返回节点继续。

设计行为：

1. 区分独立流程消息与跨池协作，说明是否需要 MessageFlow；目标流程优先用正式授权目录选择，能确定的目标信息由服务端校验后展示。
2. 不让普通设计者理解 outbox、环境变量命名或内部接口路径才能完成配置；相关内容放在管理员高级详情。
3. 新令牌只在必要的录入/绑定阶段出现；完成后显示凭据名称/状态，不能在模型、草稿、截图或日志中保留令牌。
4. 检查结果分开显示“配置通过”“认证通过”“业务投递已验证”，不合并成模糊的绿色已连接。
5. 明确检查目标和副作用；真实消息联调使用隔离实例。没有权限时不能通过深链接绕过服务器检查。
6. 向导取消/失败后回到原设计并保留字段；完成后刷新端点目录，避免必须整页重载。

验收：从空端点目录开始，管理员经前端完成准备，设计人员返回原模型完成 F/G；既不需重画，也不需手工编辑 BPMN 或复制环境配置。若仍需运维补资源，本任务标 partial 并列出明确缺口。

### U05：把错误列表做成可执行的问题清单

页面入口：[现有校验弹窗](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/ProcessDesigner.vue:149)。

设计行为：

- 在现有校验能力上增加持久问题面板，按根流程/节点分组，优先显示阻断问题；不重复创建独立诊断来源。
- 每条问题显示节点业务名、原因、建议动作。编码、元素 ID 和追踪编号可展开/复制。
- 点击问题复用现有定位能力，同时打开相关属性分区并将焦点落到问题字段；修复后重新验证该结果是否仍适用。
- 长错误不依赖悬浮才能读完；顶部提示仅用于短确认，不承载必须记住的失败原因。
- 未保存编辑导致预检失效时标“需要重新检查”；不能继续显示过期的绿色通过。
- 未知节点/旧版本诊断禁用定位并解释原因；不得定位到当前模型另一个同名节点。

文案示例：

> C02 调用子流程：输出目标 childCount 未获得系统写入资格。请检查该结果字段的回填设置。来源：父流程确认表单。

> 第二池“合作方处理”：尚未配置发起范围。请设置哪些人可以发起此流程。

验收：C/G/F 所有已知阻断错误均可从列表定位并理解下一步；从问题面板到目标字段不超过两次明确点击。不自动改类型、不自动放宽权限。

### U06：保存、发布和试运行各有清楚含义

页面入口：[设计页面](/D:/ruoyiflowable/ruoyi-ui/src/views/workflow/model/design.vue)、[模型列表](/D:/ruoyiflowable/ruoyi-ui/src/views/workflow/model/index.vue)、[工具栏](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/designer/DesignerToolbar.vue)。

| 状态 | 页面含义 | 可执行动作 |
| --- | --- | --- |
| 草稿已保留 | 编辑内容安全保留，业务配置可能未完成 | 继续编辑、恢复或明确放弃 |
| 正式设计已保存 | 当前内容已通过保存合同并保存 | 发布检查、继续编辑 |
| 发布检查通过 | 指定内容/修订在检查时满足发布条件 | 正式发布，服务端仍重新核验 |
| 已发布 Vn | 用户可发起的是这个正式版本 | 查看版本、发起隔离试运行、创建后续版本 |
| 当前修改未发布 | 画布与正在使用的版本不同 | 显示差异并继续编辑/发布 |

设计行为：

1. 页面可从保存自然进入发布检查；保留现有列表发布入口，两者共用相同服务合同。
2. 发布确认展示涉及根流程、范围、子流程/DMN 绑定版本、端点准备情况及阻断项；不把开发日志塞入产品流程。
3. 说明“固定版本”和“发布时最新版”何时冻结；发布成功显示真实服务端版本/修订，失败保留设计内容。
4. 画布动画标为“流程模拟”；真实试运行使用正式部署及隔离业务键，展示真实实例链接和结果。
5. 只对真正有影响的发布/覆盖操作做一次清楚确认，避免每次普通编辑重复打断。

验收：设计版本、已发布版本和试运行实例一致可追溯；不出现保存成功却被误以为已上线的状态。预检后资源变化时显示准确拒绝原因，旧正式版本仍可正常使用。

### U07：用业务语言表达当前状态

页面入口：[流程详情](/D:/ruoyiflowable/ruoyi-ui/src/views/workflow/work/detail.vue)、[等待事件](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/ProcessWaitingEvents.vue)、[流程图](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/ProcessViewer.vue)、[联调面板](/D:/ruoyiflowable/ruoyi-ui/src/components/workflow/RuntimeEventConsole.vue)。

设计行为：

- 详情顶部先显示当前状态、需要谁处理、下一步。并行任务显示剩余办理数量和节点；已完成实例不把最后一个历史审批写成正在处理的“当前任务”。
- 定时器：“等待系统自动继续，预计到期……”；外部事件：“等待接收方回执，当前无需审批”；异常重试：“系统正在重试，最近失败时间……”。不把技术 WAITING 统一叫待领取。
- 状态图使用文字/图标和颜色共同表示：已完成、处理中、等待外部事件、竞争取消、终止、未知；提供图例和可访问的文本轨迹。
- D 消息胜出后显示“消息已接收，信号等待已取消”；依据后端事实，不能仅改 CSS 掩盖错误投影。
- 普通审批人默认看业务说明；执行主键、请求标识、重试次数等放进有权限的技术详情。
- 操作成功后刷新待办、等待状态和轨迹；可见页面受控轮询并显示更新时间，失败退避。离开/后台暂停，返回重新查询，保留手动刷新。
- 自动更新不覆盖正在填写的表单、不抢焦点、不把已过期任务继续显示为可提交；服务器仍最终校验。

验收：用户无需依靠节点颜色猜测路径；事件竞争两种胜出、并行剩余任务、定时器推进、退回重提和终止均表达准确。页面稳定运行时操作结果目标在 5 秒内刷新可见，该指标衡量页面更新，不承诺引擎精确 5 秒调度。

### U08：改善大图操作、信息密度和无障碍

基于现有界面逐项优化，不整体更换设计系统：

1. 工具栏保留当前功能，为高频动作提供清楚名称/提示和一致禁用原因；纯图标按钮提供可访问名称。
2. 复用可调整宽度的属性面板，增加分区导航和必填项摘要，减少寻找字段时的长距离滚动；不让固定操作区遮住最后一项配置。
3. 增加节点名称搜索与多池/子流程大纲，支持定位、聚焦选中和返回原视图；复用小地图，不能把整个长图永久缩成不可读的缩略图。
4. 重要字段名、任务名和错误信息可完整查看；缩略展示有清楚展开方式，不依赖鼠标悬浮作为唯一阅读手段。
5. 统一“发起范围、办理人、会签、或签、系统回填、发布检查”等术语。内部实现词移入高级信息，不增加每次操作必须阅读的技术说明。
6. 检查 1366×768、1440×900、1920×1080，以及浏览器 200% 缩放：核心操作可达、面板可滚动、无按钮遮挡；BPMN 画布允许平移，不要求整张长图同时清晰显示。
7. 验证 Tab 顺序、可见焦点、Esc 关闭与返回触发点、键盘操作下拉和错误定位、输入法编辑。撤销快捷键不能误伤正在编辑的文本。
8. 用工具测量实际文字/交互对比度并检查屏幕阅读器通知，不凭截图宣称无障碍合规。敏感操作、等待状态和错误不能只靠颜色区分。

验收：四种固定模型在目标窗口可正常编辑；仅用键盘可完成表单配置、错误定位、保存及取消离开；核心工作流程不要求操作者预先知道技术 ID。

## 5. U09 可执行的用户验收脚本

每轮建议至少覆盖首次使用者和熟悉系统者，包含设计、审批、集成管理三类角色。小样本用于发现问题，不外推总体统计结论。无人参与时执行专家走查并明确标记，后续用户验证仍待完成。

| 编号 | 任务脚本 | 成功判定 |
| --- | --- | --- |
| UX-T01 | 导入 F 双池，找到未配置范围并只修复第二池 | 不需问开发、不误改主池，保存回读一致 |
| UX-T02 | 编辑长图，在未配端点时进入端点页，再返回/刷新 | 内容不丢，可恢复原节点，无需重画/重导入 |
| UX-T03 | 将配置过消息处理器的事件改为信号，撤销再重做 | 无需删除节点，保存部署并真实触发信号 |
| UX-T04 | 将子流程结果映射到父只读结果字段 | 理解方向及资格，实际回传正确，不能伪造修改 |
| UX-T05 | 从空端点目录完成授权资源配置并返回原模型 | 成功补齐资源并发布，失败/无权限时知道下一步 |
| UX-T06 | 处理 C/G/F 的代表性校验错误 | 每个错误可定位、原因可理解，无盲目切换/删除 |
| UX-T07 | 保存修改但不发布，再辨认哪个版本可供用户发起 | 能准确区分草稿、正式保存和已发布版本 |
| UX-T08 | 打开 D 消息胜出及 A 并行/定时等待的详情 | 30 秒内说明发生了什么、正在等谁/什么、自己是否需操作 |
| UX-T09 | 两标签并发编辑同一模型并遭遇修订冲突 | 能保留当前工作，明确选择后继续，没有静默覆盖 |
| UX-T10 | 网络中断或登录过期时保存，再恢复会话 | 不误报已保存，不丢内容，不反复提交重复副作用 |
| UX-T11 | 用键盘及 200% 缩放完成配置、定位错误和保存 | 操作可达、焦点明确、无关键信息遮挡 |

指标和门槛均为计划目标，尚未测量：

- 验收脚本中设计内容丢失为 0；为绕过系统错误而删节点/删线/重画为 0。
- 已知阻断错误的定位与处理建议覆盖率 100%；从问题到目标字段不超过两次明确点击。
- 操作成功后页面刷新目标不超过 5 秒（测试网络和后端正常条件）；失败时显示状态未知/更新失败，不以旧值伪装实时。
- 关键任务测试样本必须全部完成，或存在明确且符合权限合同的拒绝；求助次数和耗时按实际记录，与 U00 比较。
- 典型状态理解目标 30 秒内；未达到时优化表达并重测，不由开发人员代答。
- 不声称已达到特定无障碍等级；发布前记录工具检测、人工键盘及辅助技术验证的实际范围。
