# 审批功能对照清单

## 1. 对照原则

参考工程用于确认功能语义和用户工作流，目标工程不按文件逐行复制。满足以下条件才算完成一项功能：

- 用户可以从真实页面进入并完成操作。
- 前端调用目标后端 API。
- 后端执行真实权限、对象授权、状态和参数校验。
- Flowable 与 `wf_*` 数据在同一事务中形成正式结果。
- 页面、接口、运行态、历史、审计和附件回显一致。
- 正常、异常、越权、重复和并发分支具有真实验证证据。

## 8. 权限与菜单

53 条记录的固定组成：

- 2 个目录：流程管理、办公管理。
- 11 个页面：分类、表单、模型、部署、实例运维和六类办公列表。
- 40 个按钮：查询、增改删、设计、部署、状态、发起、办理、导出和附件等权限。

五角色权限必须通过以下矩阵：

1. 应有页面和按钮可见。
2. 不应有页面和按钮不可见。
3. 直接调用有权 API 成功。
4. 直接调用无权 API 返回 403 且无副作用。
5. 有 URL 权限但无对象权限时仍返回 403/404。
6. 非法状态返回 409 且运行态、历史和业务表不变化。

当前真实 HTTP 报告已覆盖 5 个角色与 70 个入口的 350 个 URL 权限单元：166 个允许、
184 个拒绝，全部通过且清理后零残留副作用。该报告关闭 URL 权限与对应允许入口的真实
HTTP 执行，不替代同角色错误对象关系、全部非法状态组合、浏览器可见性和并发故障矩阵。
