# 扩展目录查询与删除

管理页 `GET /workflow/extension/list` 只读取扩展目录及最新版，保持名称排序和非 JAVA 实现键隐藏，不读取历史部署资源。

| 服务端 Boolean | 含义 |
| --- | --- |
| `deleteAllowed` | 列表当前能证明目录已停用、非内置且没有版本；有版本的目录尚未核验引用，恒为 false。 |
| `deleteCheckAllowed` | 已停用、非内置，允许用户发起单条删除核验；不承诺最终可删除。 |

前端删除入口仅消费 `deleteCheckAllowed === true`。点击后调用 `GET /workflow/extension/{extensionId}/deletion-check`，该接口要求 `workflow:extension:remove` 权限，在只读事务中复核目录状态及正式部署引用。仅核验成功返回 `data.deleteAllowed: true`，随后才出现带目录名称的删除确认。失败保留当前列表；另一行检查、筛选、刷新、页面停用或卸载使旧检查及旧确认失效。同一行检查期间不能重复发起请求。

`DELETE /workflow/extension/{extensionId}` 的权限、事务、目录锁及版本先于目录删除的外键顺序不变；服务端在锁内重新校验全部条件，不接受前次检查作为授权凭证。检查之后目录被启用或删除、出现新引用或资源损坏，仍会拒绝最终删除。可删除的有版本目录仍可通过检查、确认、最终删除完成清理；已部署、内置或启用的目录不能删除。

低频引用核验通过 Flowable `RepositoryService` 按部署时间和主键分页，每批最多 100 个业务资源子部署，在同一可重复读事务内读取，发现目标稳定键或版本引用即拒绝。缺失、损坏、未知协议的清单，非数组或 null 的必需列表，以及缺失/非正版本 ID 或空稳定键均按数据错误拒绝；不会跳过异常后允许删除。无版本目录无需扫描历史。此设计没有新增索引、表、缓存或第二份部署快照；历史资源完整性故障影响删除检查，目录读取仍可用。分页限制单批内存，完整的无引用证明仍需遍历历史，不承诺恒定时延。

验证包括真实 Flowable/H2 部署资源、正式目录 Mapper 与 Spring 事务、真实 MySQL 结果构造、启用/内置/版本能力矩阵、205 个历史资源的分页及零列表资源访问、核验后状态/引用变化、MVC 方法权限、Vue 编译后 setup 与 KeepAlive 生命周期。浏览器登录操作和生产历史资源规模压测不在这些测试的覆盖范围内。
