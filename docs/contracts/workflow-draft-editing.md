# 表单编辑、草稿与发起

`ProcessFormRenderer` 的值由父级持有。子级从 `modelValue` 和模板默认值投影展示，只从真实编辑事件产生一次 `update:modelValue` 和一次 `change`。嵌套行透传实际字段名，不修改传入模型；加载、切换与外部重置没有编辑事件。控件局部上传队列仍等待父级回写，附件在途禁止保存/提交，提交投影只携带附件 UUID。公开事件、字段 JSON、权限及必填反馈不变。

草稿创建、保存沿用当前事务的 actor、定义和权限化部署表单，字段处理直接消费一次解析的根节点。草稿允许不完整的必填字段，但仍拒绝未知、隐藏、只读字段、非法值及附件引用。响应直接使用本次结果，仅补读数据库生成的 revision 和时间。独立详情请求重新取得当前身份和定义可用性；写入响应不重入完整表单查询。

持久化表单通过模板原有严格配置单次解码：拒绝重复键、尾随根、超过 1 MiB 的 UTF-8 正文和超过 100 层的 JSON；字符串及其他解析限制沿用同一 Jackson 配置。字段遍历在消费权限时检查明确布尔标志、权限组合、组件对象及 children 数组，不重新执行作者模板的布局、静态内容和组件全量审计。解码/字段结构损坏仍返回 500“流程部署表单快照结构异常”，cause 保留具体表单异常；拒绝发生在草稿写入、附件迁移和实例启动之前。

人工提交仍只允许默认租户的最新激活定义，绑定来自真实流程定义的 key、version 和 deployment。列表只查询摘要及这组关系，在当前页批量读取定义、最新版及发起权限，逐草稿决定能力；不装载正文，也不把第一份草稿的关系结果用于其他草稿。列表能力表达定义/权限可用性，实际打开或写入时再读取本次需要的正文。详情、保存、提交对用户曾填写的正文与同一部署正文作一次比较，损坏返回 `DRAFT_SNAPSHOT_MISMATCH`，不再叠加元数据、正文摘要、成员快照的逐项对账。原摘要列继续按既有持久化协议写入，不充当第二个授权来源。

已知定义删除、挂起、版本过期、绑定变化、无发起权限有明确不可用原因。未知异常、缺失权限决定和 500 系统故障直接失败，不转换为不可编辑或默认可提交。正式提交作为独立写请求，保留所有者过滤、当前发起授权、部署/草稿/最新版锁、revision CAS、提交值规则、附件归属和生命周期、引擎结果核验、同事务回滚与已提交幂等返回。

没有表结构、存储格式或对外 API 迁移，回滚采用同一发布单元的代码回退。数据库摘要、冻结元数据和终态审计保留原格式。

`WorkflowProcessStartChainIntegrationTest` 验证草稿幂等提交、revision 冲突、嵌套权限及失败回滚，使用真实 Flowable/H2、Spring 事务和 Mapper，不证明 MySQL 锁行为。申请草稿浏览器回归见[贡献指南](../../CONTRIBUTING.md#浏览器回归)。
