# 参数和字典类型删除契约

`DELETE /system/config/{configIds}` 与 `DELETE /system/dict/type/{dictIds}` 各自是一个完整的集合命令，保持原来的 ID 数组、权限、响应结构和受保护项提示。目标已不存在时拒绝整个请求，提示“参数配置不存在或已删除”或“字典类型不存在或已删除”，不留下部分删除。空集合不产生副作用。

## 原子性与引用

- 参数服务在同一事务内锁定目标参数集合，按请求顺序拒绝内置参数，再执行一次批量删除。参数的内置标志和缓存键来自锁定记录。
- 字典类型服务先锁定目标类型集合，再通过当前读取得引用事实，按请求顺序拒绝已有数据的类型，最后执行一次批量删除。停用数据也属于引用；类型名的比较沿用 MySQL 字段排序规则。
- 字典数据新增、修改转入以及字典类型改名必须经现有服务事务。数据写入先锁定目标类型；类型改名先锁定原类型，再同步数据。删除先取得锁时，等待中的新增、转入或改名在锁释放后拒绝已不存在的类型；引用写入先取得锁时，删除等待提交后拒绝该引用。
- 类型锁和引用当前读覆盖整个操作，不能移到仅包含最后一条写语句的事务中。当前读不依赖调用者已有的 Repeatable Read 快照，MyBatis 锁查询不复用会话查询缓存。
- 本次不改变数据库结构或持久化格式。现有 MySQL InnoDB 表及字典类型唯一键是运行基础；此协议约束应用服务写入口，直接 SQL 写入不经过应用锁协议。

## 提交与缓存恢复

业务拒绝、数据库写入失败或外层事务回滚时，所有目标保持原状，删除操作不失效缓存。只有外层事务实际提交后，才批量失效本次涉及的参数键或字典类型键。字典数据转移和类型改名同时失效原类型与目标类型缓存。

提交后的缓存故障保留原始异常并通过现有错误处理返回。此时数据库已经提交，不能向使用者声称删除已回滚，也不应通过重新创建记录来补偿数据库。恢复缓存连接后，使用现有参数管理或字典管理的“刷新缓存”入口：

- `DELETE /system/config/refreshCache`
- `DELETE /system/dict/type/refreshCache`

刷新入口清空相应缓存，再从已提交数据库重新加载。部署无需数据迁移；代码回退不恢复已经成功删除的数据，也会撤销本契约的并发保护。
