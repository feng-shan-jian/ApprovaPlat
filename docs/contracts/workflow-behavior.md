# 审批业务行为契约

## 通用完成标准

每个审批能力必须同时具备真实页面或受控机器入口、真实后端 API、权限和对象授权、状态校验、正式持久化、审计追踪以及失败零副作用。按钮可点击、接口返回成功或构建通过都不能单独证明业务完成。

## 身份与权限

- 候选用户、角色和部门必须从正式身份目录解析，并验证存在、启用和去重。
- 客户端传入的用户 ID、流程发起人或数据范围不能扩大当前登录用户权限。
- 五个职责角色为 `workflow_admin`、`workflow_designer`、`workflow_starter`、`workflow_approver`、`workflow_auditor`。
- 管理员权限、设计权限、发起权限、办理权限和审计只读权限必须保持职责分离。

## 流程状态与动作

| 动作 | 核心约束 |
| --- | --- |
| 发起 | 使用最新激活定义或明确版本，校验部署表单快照、身份、变量和附件绑定 |
| 认领/取消认领 | 当前用户必须属于有效候选范围；重复或过期任务返回稳定冲突结果 |
| 完成 | 校验 assignee、delegation、任务表单和附件，提交后核对下一活动任务 |
| 委派/委派办结/转办 | 目标用户必须有效，owner、assignee、意见和审计必须保持一致 |
| 退回 | 只允许能够证明唯一且处于安全作用域的目标；跨并行或多实例边界时拒绝 |
| 驳回 | 以整实例原子终止表达 `rejected`，不得残留活动兄弟任务或覆盖终态 |
| 撤回 | 操作人必须真实办理过前驱，且直接后继没有产生不可逆业务结果 |
| 取消 | 仅发起人对运行中的本人实例执行，并保存明确原因 |
| 终止 | 仅管理员执行，终态优先于 Flowable 自然完成事件 |
| 挂起/激活 | 写命令受状态约束；具备对象权限的参与者仍可按规则只读查看 |
| 已结束实例删除 | 仅管理员对满足引用和保留策略的终态实例执行 |

非法状态、过期 `taskId`、重复提交和执行树漂移应返回稳定的业务冲突结果，并确保运行态、历史、业务表、附件和审计没有部分提交。

## 多实例与复杂执行树

- 多实例成员由服务端身份解析器生成并保存不可变成员快照。
- 动态加签和减签必须使用 revision/CAS 或等效并发保护，并对真实 execution、活动任务和审计结果写后核对。
- ALL 会签只有全部有效成员完成后才能离开节点；ANY 或签由首个有效完成原子取消其余 sibling。
- 动态多实例节点不支持无法证明安全的退回；页面隐藏入口，直接 API 返回冲突且零副作用。
- `${multiInstanceHandler.getUserIds(execution)}` 和 `${userTaskListener}` 只能解析到固定白名单 Bean，不能执行任意表达式或任意 Java 类。

## 表单、附件与快照

- 表单模板可编辑，部署时必须固化到 `wf_deploy_form`；已部署流程不回读后来修改的模板。
- 内嵌 BPMN 表单与正式模板使用统一快照结构，并保存明确 `source_type`。
- 发起和办理都按部署快照校验字段、类型、必填、长度、选项和附件引用。
- 临时附件只有所有者可以删除；绑定后按流程对象授权读取。容量检查先锁全局配额行，再锁用户配额行。
- 业务删除先留下正式生命周期记录，物理清理失败必须进入持久化重试，而不是丢失状态。

## 扩展、连接器、DMN 与运行事件

- BPMN 扩展目录和版本不可绕过服务端已安装处理器白名单；部署时保存不可变执行快照和校验和。
- HTTP 连接器只能访问登记端点；SQL 连接器只能使用登记数据源和受控查询能力，不能接受任意 JDBC 配置或任意写 SQL。
- 连接器调用使用正式幂等台账，重试不能产生重复外部副作用。
- DMN 部署必须通过 XML 安全校验，并在流程部署时固化引用快照。
- Message、Signal 和 ReceiveTask 运行事件使用独立集成 Token；Token 正文不落库，只保存前缀、哈希、限流状态和完整调用审计。

## 边界定时器、审批 SLA 与升级

- BPMN timer 的建模、XML 往返和 Flowable job 创建不等于审批 SLA 运行能力。只有绑定正式 SLA 规则、业务日历、通知策略和升级路径，并能在真实异步执行器中完成状态变更、持久化、审计和补偿，才算可执行支持。
- SLA 规则必须绑定流程定义版本和活动/边界事件快照，保存计时起点、截止时间、日历、时区、暂停策略、提醒节点、催办次数、升级目标和幂等键；已部署版本不可回读后来修改的规则。
- 截止时间按服务端业务日历计算，明确工作日、节假日、工作时段、跨时区和节假日覆盖规则。禁止用浏览器本地时间或简单自然日加法作为最终判定。
- 实例、任务或流程被挂起、撤回、终止、驳回或进入补偿状态时，SLA 计时必须按规则暂停、取消或转入补偿；恢复时只能从正式持久化的剩余时长/日历游标继续，不能重复创建计时器。
- 提醒、自动催办和升级由异步执行器以持久化租约/CAS 或等效幂等机制触发。同一 SLA 节点在并发轮询、节点重启和重试下最多产生一次业务动作；通知失败必须进入可重试状态，不能提前写入“已通知”终态。
- 自动动作只能在服务端执行并验证流程对象权限、候选范围、租户/部门数据范围和当前状态；客户端传入的接收人、升级人或任务 ID 不得扩大权限或绕过状态校验。
- 每次判定、暂停/恢复、提醒、催办、升级、通知重试、回滚和人工处理都必须写入审计，记录规则版本、截止时间、执行器、幂等键、前后状态和失败原因，不记录 Token 或敏感正文。
- 任何通知、任务更新、升级路由或 Flowable 命令失败时，业务状态和审计必须按事务边界回滚或进入明确的持久化补偿队列；不能出现页面显示已升级而任务、数据库或 Flowable 状态未变更的部分成功。

## 错误与审计

- 参数错误、未认证、无权限、对象不可见、非法状态和内部失败必须具有稳定且可测试的响应语义。
- 拒绝请求不能写入 Flowable、`wf_*`、附件文件或操作日志中的成功业务结果。
- 审批意见、操作者、目标对象、前后状态和必要的幂等标识必须可追踪；日志和报告不得保存密码、Token 或敏感业务正文。
